# Agent 空间｜产品说明

## 1. 产品定位

Agent 空间是一个面向组织提效的多人、多 Agent 协作空间。

人与各自的个人 Agent 在共享上下文中参与工作，由空间 Agent 协调推进，结合通用及专业 Agent 的执行能力，完成从需求提出、信息同步、分歧处理到结果交付的全过程。

产品希望让团队在成员不必始终在线、反复解释背景和人工协调的情况下，仍然能够持续推进工作。人保留责任、授权和关键判断，Agent 承担更多执行与协作事务。

本文描述的是产品的目标形态，具体能力可分阶段实现。

## 2. 产品初衷

Agent 帮助个人提效，已经呈现出清晰的使用方式：人提出需求，Agent 思考、操作、交付，遇到不确定的问题再向人询问。

但个人效率的提升，不会自动变成组织效率的提升。

真实工作往往涉及多个人。一个结果能否达成，除了取决于每个人完成任务的速度，还取决于信息是否同步、依赖是否明确、分歧能否解决，以及需要判断的人能否及时响应。

当执行能力被放大之后，组织中的协调与判断甚至可能成为更突出的瓶颈：产出更多，等待审阅的内容也更多；每个人的 Agent 更了解自己的主人，但彼此掌握的信息仍然不同。

Agent 空间希望进一步解决这些问题，让 Agent 从个体的执行助手，发展为组织协作的参与者。

## 3. 我们看到的问题

### 3.1 个人与组织的瓶颈不同

个人经常受限于执行能力、时间和精力。组织还受到成员之间协调方式的影响。

一项工作即使已经完成，也可能因为等待另一个人确认、补充信息或作出取舍而无法继续。单点任务变快，并不代表整体周期缩短。

### 3.2 上下文分散，成员依据不同的信息工作

背景可能存在于文档、私人会话、本地文件和线下沟通里。成员看到的目标、约束和结论可能并不一致。

信息差会带来重复解释、误解和返工，也会制造一些本可以提前避免的分歧。

### 3.3 协作依赖人的持续在线

同步进展、寻求帮助、解释原因和确认安排，往往需要找到相应的人。

但并非每一次沟通都需要本人参与。许多事实同步和已有标准下的判断，可以由了解这个人的 Agent 先行处理。

### 3.4 现有 Agent 能力主要集中在单点执行

开发、测试、文档等专业 Agent 可以扩展产能，但团队还需要持续维护共同上下文、协调责任与依赖、处理分歧，并判断什么时候应该请人介入。

组织提效需要覆盖执行之间的连接过程。

### 3.5 经验未能持续影响后续工作

任务完成后，团队常常留下结果，却没有留下判断依据。

为什么采用这个方案、什么情况被打回、负责人在意什么，往往仍然存在于个人记忆里。成员离开后，后来的人需要重新摸索。

## 4. 对未来的判断

### 4.1 个人 Agent 会持续了解并代表主人

个人 Agent 会在日常工作中积累对主人的理解，包括工作习惯、专业经验、判断依据、质量标准和沟通方式。

随着理解和授权逐步建立，它能够代表主人同步信息、表达立场、参与讨论，并处理一定范围内的事务。

### 4.2 Agent 之间的协作会成为组织工作的重要组成

未来的协作环境里，人和 Agent 会同时参与。

个人 Agent 可以关注相关变化、请求帮助和表达约束；空间 Agent 可以组织工作与协调分歧；专业 Agent 可以承担执行。人随时能够参与，也可以将日常推进委托出去。

### 4.3 共享上下文是组织级协作的基础

当多个 Agent 共同工作时，必须能够访问一致、可追溯的公共事实，包括任务、资料、产物、决策与团队标准。

共享上下文能够减少信息差与转述损耗。个人的私有资料和判断仍然保留独立边界。

### 4.4 责任归属与执行能力可以分开

人的角色不应只由执行工作量定义。

一项工作可以由具体的人承担责任，通过个人 Agent 参与判断，再调用适合的 Agent 执行。执行能力可以按需扩展，责任和授权需要始终清楚。

### 4.5 自主程度需要逐步建立

模型目前仍然存在理解偏差、遗漏与判断错误。

产品需要允许人在不同阶段介入，通过真实结果和反馈建立信任，再逐步扩大 Agent 可以独立处理的范围。

## 5. 产品目标

产品的核心目标是：

**减少团队从提出事情到完成事情之间的协调损耗，让工作能够持续推进，并保持结果可信、责任清楚。**

具体包括：

- 减少重复解释背景和人工同步信息的成本。
- 减少因信息差、依赖不明和成员不在线造成的等待。
- 让分歧有明确的协调过程和终止机制。
- 将执行能力按任务需要调配，同时保留具体的责任人。
- 将人的反馈转化为后续协作可以使用的标准。
- 让共享知识和工作积累在人员变化后仍然留存。

## 6. 空间的定义

空间是承载共同工作及其上下文的持续协作单元。

一个空间可以围绕明确的项目或阶段目标建立，也可以长期服务于一个产品组、部门或协作团队。目标是可选项，空间不强制设置截止时间或生命周期。

空间包含：

- 成员及其个人 Agent。
- 属于空间的协调 Agent。
- 可调用的通用及专业执行 Agent。
- 任务、请求、讨论与产物。
- 共享资料、决策记录与团队标准。

成员离开后，空间及其公共积累继续存在。个人 Agent 和私有信息随本人保留。

## 7. 角色与职责

| 角色 | 核心职责 | 归属 |
|---|---|---|
| 人 | 提出需求、补充信息、授权、确认结果、作出关键判断并承担责任 | 个人 |
| 个人 Agent | 理解并代表主人，关注相关变化、同步状态、表达立场、预审交付、汇总待处理事项 | 个人 |
| Owner 的个人 Agent | 在个人 Agent 职责之外，依据 owner 的授权承担分歧终止与决策职责 | 权力随 owner 身份转移 |
| 空间 Agent | 整理任务、协调分工、组织讨论、路由求助、维护共享上下文与团队标准 | 空间 |
| 通用及专业 Agent | 根据任务需要执行工作，报告进展、提交产物与验证依据 | 可调度的执行能力 |

个人 Agent 不需要拥有所有专业能力。它的核心价值，是将主人的理解、标准和立场带入协作。

空间 Agent 对共同工作负责。Owner 的个人 Agent 代表负责人行使授权，两者职责需要区分。

## 8. 上下文与归属

### 8.1 空间共享层

共享层保存团队共同工作的事实和资产：

- 目标、约束与优先级。
- 任务、验收标准、责任人与依赖。
- 公开进展、讨论、产物和版本。
- 决策结果及其依据。
- 团队标准、共享资料与交接记录。

共享内容应当有来源、更新时间和修改记录。共同事实发生变化后，需要识别相关任务与成员，推动必要的同步。

### 8.2 个人私有层

私有层保存个人 Agent 对主人的理解：

- 个人判断手册与工作偏好。
- 未公开的资料和沟通。
- 私有约束与授权边界。
- 主人在不同空间中的工作负担。

空间匹配分工时，使用本人同意公开的档案。个人 Agent 对外表达时，应当遵守授权范围，避免泄露私有信息，并对表达的事实负责。

## 9. 核心使用流程

### 9.1 创建空间

发起人创建空间，补充用途、背景和相关资料，并邀请成员。

有明确目标时，可以与空间 Agent 一起补充约束和成功标准；常设团队也可以直接开始协作。

### 9.2 成员与个人 Agent 加入

成员确认加入后，其个人 Agent 获得相应的空间访问权限。

空间 Agent 根据公开档案了解成员分工，并在需要时推荐责任安排。成员能够确认或调整自己的职责。

### 9.3 接收新的工作

工作可以来自：

- 人直接提出的任务。
- 明确目标下的主动拆解。
- 成员或个人 Agent 的求助。
- 外部事件与系统变化。
- 现有工作引出的后续事项。

人可以指定负责人或执行 Agent，也可以交给空间 Agent 协调。

### 9.4 整理与分工

空间 Agent 对输入进行澄清、修正、拆分或合并，形成可推进的工作事项。

每项工作需要明确：

- 要完成什么。
- 谁承担责任。
- 谁负责执行。
- 依据什么判断完成。
- 存在哪些依赖与限制。

对模糊目标，应先澄清关键问题，避免直接生成缺乏依据的大量任务。

### 9.5 协作执行

执行 Agent 根据共享背景和相关标准开展工作，报告有意义的进展，并提交实际结果。

个人 Agent 根据主人的职责参与补充标准、响应问题和检查相关变化。

执行中出现新的信息，应更新共享状态，并通知受影响的参与者。

### 9.6 分歧处理

空间 Agent 整理问题、相关事实、各方立场与可选方案，组织必要的讨论。

可以依据已有规则解决的事项，在授权范围内处理；需要终止分歧时，由 owner 的个人 Agent 按授权作出决定，超出授权则交给 owner。

讨论需要有轮次或时间边界。决策应留下依据、授权来源和影响范围，并允许有权限的人纠正。

### 9.7 交付与反馈

交付应包含结果、完成依据，以及尚未解决的问题。

验收方式根据任务性质和授权确定：

- 可通过可靠证据核验的事项，可以自动完成。
- 需要主观评价、重要取舍或明确人工验收的事项，由个人 Agent 先给建议，再交给人确认。
- 证据不足、检查失败或结果矛盾时，明确暴露异常。

人的通过或打回意见，可以经确认后沉淀为团队标准，供后续工作使用。

## 10. 任务之外的协作

空间还应支持持续的信息同步和互助。

例如：

- 某项方案变化后，相关个人 Agent 识别对主人工作的影响。
- 个人 Agent 定期同步已获授权的进展和阻塞。
- 成员请求帮助，空间 Agent 找到相关经验、资料或协作者。
- 同一个人在多个空间的安排发生冲突，由其个人 Agent 汇总并提出调整建议。

这些协作可以形成任务，也可以通过信息补充或已有结论直接解决。产品不应要求所有输入都先被包装成任务。

## 11. 人的介入与控制

人能够随时查看进展、补充信息、参与讨论、调整分工或停止执行。

系统需要清楚表达：

- Agent 正在替谁做什么。
- 当前行为依据哪些信息和授权。
- 为什么需要本人介入。
- 决定之后会影响哪些工作。

个人 Agent 应汇总主人参与的多个空间中的事项，过滤重复信息，提供上下文和建议，减少用户逐个空间检查的负担。

## 12. 记忆、反馈与交接

空间记忆应当来自真实协作过程，重点记录：

- 决策及其原因。
- 标准的形成、修改和停用。
- 关键背景与约束变化。
- 人员和责任交接。

个人偏好与团队标准应分别管理。一次反馈是否适用于整个团队，需要有明确范围，并允许人修正。

成员离开时，应移交未完成责任、共享产物和必要背景；其私有信息不因交接而自动公开。

## 13. 产品界面原则

界面应围绕真实工作及其变化组织，帮助用户快速回答：

1. 现在有哪些事情在推进？
2. 谁负责，哪个 Agent 正在做？
3. 当前卡在哪里？
4. 哪些事情需要我？
5. 已经形成了什么结果和共识？

空间首页呈现工作进展、待处理分歧和重要变化；事项详情呈现执行、讨论、产物与反馈；个人入口汇总跨空间的关注事项和判断请求。

Agent 的过程信息需要分层展示，避免用大量执行日志占据用户注意力。视觉层级应服务于状态理解、行动和结果查看。

## 14. 衡量产品是否有效

核心指标是团队从需求提出到可信结果交付的整体周期。

辅助指标包括：

| 维度 | 关注内容 |
|---|---|
| 等待 | 等待信息、确认与决策的时间 |
| 人的注意力 | 每项结果需要多少次人工介入 |
| 协调 | 有多少问题在授权范围内得到解决 |
| 质量 | 返工、错误结项与交付缺失情况 |
| 同步 | 重要变化是否及时触达相关参与者 |
| 积累 | 团队标准和历史决策是否改善后续工作 |
| 信任 | Agent 决定被纠正、撤回或越权的情况 |

指标应结合判断。减少人工介入的同时，需要保持结果质量和人的控制权。

## 15. 阶段边界

初期应优先验证一条完整的协作闭环：

**提出工作 → 整理分工 → 执行与协调 → 交付处理 → 反馈留存。**

随后逐步增强主动同步、求助路由、跨空间协调和个性化理解。

现阶段不应假设：

- 模型能可靠拆解任何模糊目标。
- 自检通过就等于结果正确。
- 共享空间会自然消除所有分歧。
- 所有事项都适合自动决策。
- 个人 Agent 从第一天起就充分了解主人。

产品需要在这些现实约束下提供价值，并通过可追溯的协作、真实反馈与授权积累，逐步提升自主能力。
